# 离线演示版（无服务器可验收）

> 前提：**用户没有云服务器。** 但 App 必须能直接装到手机上给别人验收。
> 本文件说明离线版怎么用、边界在哪、以及怎么切回真服务器。

---

## 1. 一句话说明

App 里内置了一个**本机演示引擎**，它顶替服务端应答全部接口。
界面、错误码、离线队列、判定逻辑**完全复用同一份代码** ——
所以"离线验过的流程"就是"接上服务器后的流程"，不存在两套实现。

切换入口：**绑定页 / 登录页 → 服务器地址 → 使用本机演示模式**。
登录后的 App 顶部也有「服务器地址」图标，可随时切换。

---

## 2. 怎么演示（三步）

### 管理端（发布者工作台）

1. 打开管理端 → 顶部「服务器地址」→ **使用本机演示模式**
2. 若要求登录，邀请码填 **`1111`**
3. 工作台会显示 4 个演示活动（已发布 / 已结束 / 已取消各状态都有）
4. 点「图书馆书架整理志愿服务」→ **现场看板**：
   - 待确认 **1 人**（李娜，种子数据预置的待复核记录）
   - 名单 3 人
5. 点名单里的李娜 → 复核页（客观证据 + 评分明细 + 通过/驳回）
6. 点「通过」→ 看板变「已签到 1」

### 用户端（志愿者）

1. 打开用户端 → 服务器地址 → **使用本机演示模式**
2. 绑定页会直接显示演示凭据：

   ```
   活动编号 demo-act-library
   学号     2021001
   邀请码   DEMO0001
   ```

3. 照着填 → 绑定并进入
4. 点「去签到」→「开始签到」（会取一次真实定位）
5. 签完可在「在岗」「记录」两个标签查看抽查任务与证据

> 位置相关：种子活动的签到点是**南湖校区图书馆**经纬度。
> 若演示者不在附近，签到会因超出围栏而拿不到围栏分（这是**正确**行为）。
> 若要演示"自动通过"，请在管理端新建一个活动并用「用当前位置作为签到点」。

## 3. 演示模式的边界（必须如实告知验收者）

| 项 | 说明 |
|---|---|
| 数据位置 | 只在这台手机上（应用私有目录），**不上传任何地方** |
| 两端关系 | 管理端与用户端的演示数据**互相独立**（Android 沙箱隔离），各演示各的一侧 |
| 时间基准 | 用本机时间；真服务端以自己的时间为准 |
| 判定 | **确实执行**方案 §6.1 的评分表（围栏 / 网络辅证 / 采样一致 / 反作弊 / 阈值），不是假装成功 |
| 导出 | 演示模式下**明确拒绝**（没有服务端可生成文件），提示语会说明原因 |
| 邀请码 | 管理端邀请码固定 `1111`；参与者邀请码形如 `DEMO0001` |

界面在演示模式下的服务器设置里会写明：
> 当前：本机演示模式（数据只在这台手机上，未连接任何服务器）

## 4. 怎么切回真服务器

同一个入口 → 填写地址 → **测试连接** → 保存。

- 地址只写"主机:端口"即可，会自动补 `http://` 与 `/api`
  （例如 `192.168.1.5:8080` → `http://192.168.1.5:8080/api`）
- 「测试连接」是**一次定论**（不重试），失败最多 6 秒给结论
- 保存后回自动关闭对话框并刷新数据

地址是**运行时**配置、存在本机，换地址**不需要重新打包**。

## 5. 技术实现（给后续开发者）

```
页面 → ApiClient（重试 / 幂等键 / 令牌 / 信封解析 / 错误码映射）
                ↓
        ApiTransport          ← 只有这一层被替换
          ├── 真实 HTTP（transport == null）
          └── OfflineDemoTransport（本机引擎）
```

关键文件：

| 文件 | 作用 |
|---|---|
| `packages/shared_core/lib/src/network/api_transport.dart` | 报文层抽象（接缝） |
| `packages/shared_core/lib/src/offline/offline_demo_transport.dart` | 本机引擎：路由 + 种子 + 评分 |
| `packages/shared_platform/lib/src/offline_demo_store.dart` | 演示数据与开关的持久化（原子写） |
| `packages/shared_platform/lib/src/server_endpoint_store.dart` | 运行时服务器地址的持久化 |
| `packages/shared_ui/lib/src/widgets/server_endpoint_dialog.dart` | 地址设置 + 演示模式开关 |
| `packages/shared_core/test/offline_demo_test.dart` | 11 项端到端测试（登录/建档/名单/邀请码/绑定/签到/抽查/复核） |

为什么在报文层做接缝：如果在界面里到处写 `if (offline)`，
两套代码必然分叉 —— 离线能跑通的路径接上服务器可能跑不通，
而且每加一个功能都要写两遍。放在报文层，
`ApiClient` 之上的一切（重试、幂等、错误码、`decode`）对两种来源完全一致。

## 6. 已知限制（下一轮可改进）

1. **两端数据不共享**：真同步需要服务器。演示时靠"各演示各的一侧"绕过。
2. **导出不可用**：没有服务端就无法生成可下载文件（已明确提示）。
3. 演示数据**没有过期清理**：反复演示会累积新建的活动，
   可在服务器设置里切回服务器再切回演示来重置（或卸载重装）。
4. 演示模式的判定虽然真实执行评分表，但**不替代**服务端判定 ——
   正式数据仍必须由 `server/` 的判定逻辑产生。

## 7. 首次启动公告（App / 网页 / 服务器 的关系）

第一次打开任一端 App 会自动弹出「关于本平台」，把三部分的分工讲清楚；
勾「不再自动提示」后不再打扰，之后可随时从
**服务器地址 → App、网页、服务器是什么关系？** 重新打开。

弹窗内容（口径必须与实现一致）：

| 部分 | 位置 | 职责 | 状态 |
|---|---|---|---|
| **手机 App（两端）** | 现场 | 用户端：绑定 → 定位签到 → 在岗确认 → 我的记录；管理端：发布 → 名单 → 现场看板 → 复核 | 已交付（两端都装了） |
| **网页端** | 电脑 | 浏览活动列表/详情、按状态与部门筛选、导出 CSV | 已交付，并在另一台电脑上验收通过 |
| **服务器** | 数据中枢 | 数据同步 + **签到是否有效的最终判定** | **目前没有**；用「本机演示模式」顶上 |

三条必须明确的口径：

1. **判定权在服务器**，App 只负责采集并上报证据
   —— 不要让用户以为 App 自己能决定签到是否算数；
2. **网页端是只读**（浏览 / 导出），签到与复核只在 App 里做
   —— 因为现场判定需要定位证据；
3. **演示数据只在本机**、不会上传、也不与网页或另一台手机同步
   —— 演示结果不能当作正式记录。

> 为什么把它做成弹窗而不是写在文档里：验收者拿到 App 第一分钟就会产生
> "为什么网页看不到我建的活动"这类疑问。答案必须在**他打开 App 的那一刻**
> 就出现，否则后面每个功能都会被误解。

对应测试：`packages/shared_ui/test/platform_intro_dialog_test.dart`（5 项）
钉住了"三部分都要讲到""演示模式必须说明数据不外传""判定权在服务器"。
