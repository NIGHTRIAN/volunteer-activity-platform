# 三端联调报告：以本机为服务器

> 目的：把**管理端 App、用户端 App、网页端**同时连到同一台电脑上的服务端，
> 跑一遍真实业务链路，确认"三端数据一致、判定在服务端"的预期效果。
>
> 结论：**链路全通**，并在此过程中发现并修复了 **1 个会阻断网页导出的 bug**。

---

## 1. 环境

| 项 | 值 |
|---|---|
| 服务端 | `server/src/server.js`，监听 `0.0.0.0:8080` |
| 数据库 | SQLite，`%TEMP%\vol-demo.db`（`NODE_ENV=dev`，空库自动写入 8 条演示活动） |
| 网页 | 由服务端托管 `web/dist`，地址 `http://127.0.0.1:8080/` |
| 电脑 | `10.3.215.117/16`（WLAN） |
| 手机 | Redmi Note 12T Pro，`10.3.229.13/16`（wlan0） |
| 手机 ↔ 电脑 | **USB `adb reverse tcp:8080 tcp:8080`** |

### 1.1 为什么不用局域网 IP

两台设备在同一 `/16` 网段，但手机直连电脑 8080 失败：

```
$ adb shell toybox nc -z -w 3 10.3.215.117 8080
nc: connect: No route to host
```

这是**校园网 AP 的客户端隔离**（同一 Wi-Fi 下设备之间互不可见），
不是防火墙问题（Windows 上 Node.js 的入站规则是放行的）。

因此改用 USB 转发：`adb reverse` 让手机的 `127.0.0.1:8080` 指到电脑的 8080。
App 里配置的服务器地址仍是 `http://127.0.0.1:8080/api`，
**走的依然是你电脑上的真服务端**，只是传输层换成 USB，绕开隔离。

> 换到普通家用路由器（无客户端隔离）时，把 App 的"服务器地址"改成
> `http://<电脑局域网IP>:8080/api` 即可，服务端本身已经监听 `0.0.0.0`，不用改任何代码。

## 2. 跑通的链路

```
管理端 App                电脑服务端                 用户端 App            网页端
──────────               ──────────                ──────────           ──────
登录(1111)          →   下发 admin_session
开始活动(published→ongoing，带 from) →  校验乐观锁
批量导入名单(CSV 文件) →  participants
生成邀请码          →   invite_code
复制"整段邀请信息"   →   （剪贴板）
                           ←  粘贴邀请信息 → 自动填三字段
                           ←  bind → 活动授权
                           ←  定位签到 → 服务端评分 60 → 自动通过
现场看板            ←   已签到 2 / 待确认 0
复核（45 分转人工）→   写 reviewed_by
                                               ←  我的记录：已签到 · 60 分
                                           网页列表/详情 ←  活动、名单人数、状态
                                           导出 CSV     ←  BOM + 脱敏
```

### 2.1 各步骤实际证据

**① 管理端 App 已连上电脑服务端**

引导弹窗首行即显示：`已连接服务器：http://127.0.0.1:8080/api`。

**② 开始活动（验证 `from` 乐观锁）**

App 发 `{from:'published', to:'ongoing'}`，服务端落库
`status=ongoing, version=2, started_at=2026-10-18T16:25:59+08:00`。

**③ 用 CSV 文件导入名单（新功能在真服务器上验证）**

推送 `roster_demo.csv`（含中文表头）：

```
学号,姓名,手机号
2026101,张伟,13800000101
2026102,李娜,13800000102
```

在 App 里「批量导入 → 从 Excel / CSV 文件导入」选中该文件：

- 表头**自动跳过**（只识别出 2 行）
- 中文姓名正确解码
- 导入报告：**2 总行数 / 2 已接受 / 0 被拒绝 / 全部接受**

> 这一步同时回归了上一轮修的 `accepted` 字段 bug —— 修复前这里会显示
> "0 已接受 / 2 被拒绝"，而实际数据已导入，属于"错得误导人"。

**④ 跨 App 一键粘贴**

管理端点某人的「复制邀请信息」后，切到用户端点「粘贴邀请信息（自动填写）」，
三个输入框被自动填好：

| 字段 | 自动填入 |
|---|---|
| 活动编号 | `9` |
| 学号 | `2026101` |
| 邀请码 | `QF3G3FZQ` |

这一步验证了「活动码复制 + 一键粘贴」**跨应用**真的可用
（此前只在单侧验证过复制按钮存在）。

**⑤ 用户端签到，服务端判定**

张伟从手机签到（定位 + 网络证据），服务端评分明细：

```json
[
  {"reason":"围栏内且距中心 0m（≤50m）","points":40},
  {"reason":"校园网 IP 命中","points":10},
  {"reason":"多次采样一致","points":10}
]
```

合计 **60 分 = 自动通过阈值** → `status=success`。
用户端显示「已签到 · 距签到点约 0 米 · 证据评分 60（服务端计算，仅供参考）」。

**⑥ 人工复核（30–59 分区间）**

李娜用弱证据签到：`45 分`（围栏宽松 25 + 校园网 10 + 采样一致 10）→ `pending_review`。
管理端看板显示「待确认 1」，进入复核页能看到**与服务端一致的评分构成**，
点「通过」后：

```
status=success, score=45, reviewedBy=owner-demo-0001
```

**⑦ 网页端**

- 列表：`共 7 个活动`，联调活动显示「进行中」，状态汇总 进行中 2 / 报名中 3 / 已结束 1 / 已取消 1
- 详情：`已报名人数 2 人`（来自 App 导入的名单）、活动编号、坐标、签到半径、签到时段全部正确

## 3. 本轮发现并修复的 bug

### `kind=activities` 被导出白名单挡掉，**网页导出为 CSV 直接 400**

上一轮我给单活动导出加了 `kind` 白名单，只列了方案里写的
`checkin_list / participants / attendance_detail / summary / my_records`。

但**网页端实际传的是 `?kind=activities`**（`ActivityListPage.vue`、
`ActivityDetailPage.vue` 都是），不在白名单里：

```
GET /api/activities/9/export?kind=activities  →  HTTP 400
{"code":40001,"msg":"不支持的导出类型：activities"}
```

而 App 端用的是 `checkin_list`，一切正常 —— **两个客户端各用一种写法，
只测一边永远发现不了**。这正是"三端联调"才能暴露的问题。

修复：把 `activities` 加入合法值，并归一化到 `summary` 分支
（语义就是"这条活动的活动信息"）。

修复后：

| kind | 结果 |
|---|---|
| `activities`（网页） | 200，CSV 695 B，BOM `[239,187,191]` |
| `summary` | 200，CSV 695 B |
| `checkin_list`（App） | 200，CSV 345 B，含脱敏手机号 |
| `nonsense` | 400（仍然明确拒绝未知类型） |

## 4. 一个待改进的点（未改代码）

联调第一天，管理端 App 出现过一次**"点了没反应"**：

App 里保存的管理员令牌是上一个数据库的（换库后服务端已无此会话），
但 App 仍显示"已登录"。此时点「开始活动」，页面没有任何变化 ——
服务端返回的是 `40101 管理端登录已过期`，但界面上没看到明显提示，
让人以为按钮坏了。

重新登录后一切正常，因此这不是功能缺陷，而是**失败反馈不够显眼**。

建议（尚未实施）：App 启动时用 `GET /auth/admin/me` 校验令牌，
失效就直接回登录页并说明原因 —— 这个接口上一轮已经实现了。
