# 志愿活动信息平台 · 使用指南

> 面向三类读者：**发布者**（管理端）、**志愿者**（用户端）、**部署者**（服务端）。
> 全文按"先跑起来，再讲细节"的顺序组织。

---

## 0. 一句话说清这是什么

一套平台，**三个部分**：

| 部分 | 在哪里 | 干什么 |
|---|---|---|
| **手机 App（两端）** | 现场 | 用户端：绑定活动 → 定位签到 → 在岗确认 → 看记录<br>管理端：发布活动 → 管名单 → 现场看板 → 复核签到 |
| **网页端** | 电脑浏览器 | 浏览活动列表与详情、按状态/部门筛选、导出 CSV（**只读**） |
| **服务器** | 一台机器 | 数据同步 + **"这次签到到底算不算数"的最终判定** |

三条必须知道的口径：

1. **判定权在服务器**。App 只负责采集并上报证据，不自己下结论。
2. **网页端只读**。签到与复核只能在 App 里做，因为现场需要定位证据。
3. 三部分是同一套系统，不是三个独立产品。

---

## 1. 先选一种用法

| 用法 | 需要服务器吗 | 适合 |
|---|---|---|
| **A. 本机演示模式** | ❌ 不需要 | 给人演示、验收、自己上手试试 |
| **B. 连真实服务器** | ✅ 需要 | 真实使用、多台手机共用数据 |

两种用法在 App 里一键切换，**界面与判定逻辑完全一样**
（演示模式用的是同一个 `ApiClient`，只是把"网络报文"换成了本机引擎）。

## 2. 快速开始 A · 本机演示模式（不需要服务器，5 分钟）

### 2.1 安装

把这两个 APK 装到 Android 手机上：

```
apps/user_app/build/app/outputs/flutter-apk/app-arm64-v8a-release.apk    用户端 18 MB
apps/admin_app/build/app/outputs/flutter-apk/app-arm64-v8a-release.apk   管理端 18.8 MB
```

用数据线装：

```bash
adb install -r app-arm64-v8a-release.apk
```

> 只能装 arm64 版本（现代手机都是）。装不上时见 §9.3。

### 2.2 打开演示模式

1. 启动 App
2. 首屏会弹「关于本平台」→ 读完点「知道了」
   （勾「不再自动提示」以后就不再打扰）
3. 点底部/顶部的 **服务器地址**
4. 点 **「使用本机演示模式（无需服务器）」**

打开成功后，对话框里会写：

> 当前：本机演示模式（数据只在这台手机上，未连接任何服务器）

### 2.3 管理端演示（发布者视角）

1. 若要求登录，邀请码填 **`1111`**
2. 工作台显示 4 个演示活动（已发布 / 已结束 / 已取消都有）
3. 点「图书馆书架整理志愿服务」→ **现场看板**
   - 待确认 **1 人**（预置的待复核记录）
   - 名单 3 人
4. 点名单里的「李娜」→ 复核页：客观证据 + 评分明细
5. 点 **「通过」** → 看板变成「已签到 1」

### 2.4 用户端演示（志愿者视角）

1. 启动用户端 → 服务器地址 → 使用本机演示模式
2. **绑定页会直接显示演示凭据**（不用自己去查）：

   ```
   演示数据：活动编号 demo-act-library
            学号 2021001   邀请码 DEMO0001
   ```

3. 照着填 → 绑定并进入
4. 点 **「去签到」**

   > ⚠️ 演示活动的签到点是固定的（南湖校区图书馆）。
   > 你不在那儿就会判"超出范围"—— 这是**正确行为**。
   > 想演示"自动通过"，先点活动卡片下方的
   > **「演示：把签到点设为当前位置」**，再签到。

5. 授权定位 → 「开始签到」→ 采 3 次定位 → 出结果

### 2.5 演示模式的边界（**要如实告诉验收者**）

- 数据**只在这台手机上**，不上传任何地方，也不与网页/另一台手机同步
- 两端 App 的演示数据**互相独立**（Android 沙箱隔离），各演示各的一侧
- 用本机时间，不是服务端权威时间
- **导出不可用**（没有服务端能生成文件），会明确提示
- 判定**真实执行**评分表，但结果仅用于演示，不能当正式记录

## 3. 快速开始 B · 连真实服务器

### 3.1 启动服务端

```bash
cd server
npm install          # 只有内置依赖，很快
npm start            # 默认 http://0.0.0.0:8080
```

看到监听日志即可。健康检查：

```bash
curl http://127.0.0.1:8080/api/health
# {"status":"ok","service":"volunteer-server",...}
```

**首次启动会自动写入演示数据**（`NODE_ENV=dev` 时），所以打开网页能看到活动。
空库启动会是一个空页面 —— 那种状态下无法验收筛选、统计、详情、导出中的任何一项。

### 3.2 顺便把网页发出去（可选，强烈建议）

```bash
cd web
npm install
npm run build        # 产物在 web/dist
```

服务端默认会找 `web/dist`，找到就**同一个端口**把网页一起发出去
（无需 Nginx、无需 CORS）。然后浏览器打开：

```
http://<服务器IP>:8080/
```

### 3.3 让手机连上服务器

**第一步：确认手机能访问电脑。**

- 手机与电脑连**同一个 Wi-Fi**
- 查电脑 IP：`ipconfig`（Windows）/ `ifconfig`（macOS/Linux）
- 手机浏览器打开 `http://<电脑IP>:8080/api/health`，能看到 JSON 就通了

> 打不开的常见原因见 §9.1。

**第二步：在 App 里填地址。**

1. App → 服务器地址（绑定页/登录页底部，或登录后顶部的 `⟳` 旁的服务器图标）
2. 地址栏只填 **`主机:端口`** 就够，例如：`192.168.1.5:8080`
   - 会自动补 `http://` 和 `/api`
3. 点 **「测试连接」**
   - **最多 6 秒给结论**（故意不重试：地址写错时不该让你干等 30 秒）
4. 通过后点 **「保存」**

地址会**记住**，换地址不需要重新打包 App。

**第三步：登录。**

- 管理端：邀请码 **`1111`**（默认，可在服务端改）
- 用户端：用发布者给你的 **活动编号 + 学号 + 邀请码** 绑定

### 3.4 用数据线也能连（不想折腾 Wi-Fi 时）

```bash
adb reverse tcp:8080 tcp:8080
```

然后在 App 里把地址填成 `127.0.0.1:8080`。
手机上的 `127.0.0.1:8080` 会被转发到你电脑的 8080。

> 这招在"电脑连了手机热点、但 Android 热点客户端隔离导致手机访问不到电脑"时特别有用。

## 4. 管理端（发布者）操作指南

### 4.1 登录

输入邀请码 → 登录。**首次登录后本设备会被记住**，之后不用重复输。

令牌是**滑动过期**：默认 12 小时，但只要你在用就自动续期；
真正闲置 12 小时才需要重新登录。

### 4.2 新建活动

首页 → **「新建活动」**。必填与建议：

| 字段 | 说明 |
|---|---|
| 活动名称 | 必填，≤60 字 |
| 组织部门 | 必填，会用作网页筛选的部门字典 |
| 开始/结束时间 | 必填 |
| 活动地点 | 建议填 |
| **经纬度** | **必填**。点「用当前位置」最省事 |
| 签到半径 | 室外默认 300 米，室内 150 米 |
| **场地网络** | **强烈建议配**（见下） |

#### 为什么一定要配「场地网络」

评分表里：

```
围栏内（精度 ≤50m）  +40
多次采样一致         +10
                    ────
                    50     自动通过门槛是 60
```

差的 10–30 分**只能**来自网络辅证（Wi-Fi +20 / 校园网 +10），
而服务器**只在活动配了白名单时才计分**（否则谁都能填个 BSSID 骗分）。

**结论：不配这两项，志愿者每次签到都会转人工，你得一条条点。**

操作：站在场地里点 **「用当前网络作为场地网络」**，会自动读取：

```
已记录场地网络
场地 Wi-Fi：a4:2b:8c:11:22:33（+20 分）
校园网网段：10.3.（+10 分）
```

> 只读到其中一项也没关系，一项就够过门槛。

### 4.3 管名单

活动详情 → **「名单」**：

- **加人**：学号 + 姓名（学院、手机号选填；手机号用于二次核对）
- **批量导入**：每行 `学号,姓名,手机号`，逐行给结果，不会因为一行出错就整批回滚
- **移出**：软删除，记录保留（便于回答"这个人到底来过没有"），
  同时**立即作废该人的活动授权**

同一活动内学号**唯一**，重复加会提示"已存在"。

### 4.4 发邀请码

名单页 → **「生成邀请码」**。

- 已有**未使用**的码会**复用**，不会每次点都换一个
  （现场刚念完就变码会乱套）
- 码被用掉后再发，会生成新码
- 码形如 `BMJSL7XE`（去掉了容易看混的 `I/O/0/1`）

### 怎么发出去（这一步以前最容易出错）

点每行右侧的**复制按钮**，复制到的是**一整段带标签的文字**：

```
【志愿活动】图书馆书架整理志愿服务
姓名：张伟
活动编号：13
学号：2024001
邀请码：W8PWJXF4

打开「志愿活动」App，点「粘贴邀请信息」即可自动填入。
```

志愿者在绑定页点「粘贴邀请信息」即可自动填好三个框 ——
不需要他照着抄，也就不会"活动编号填进学号框"。

> 名单页顶部有一条**常驻的「活动编号」**，随时可复制
> （邀请码明文只显示一次，但活动编号是永久的）。
> 多人时点「复制全部」会一次复制多段，仍然要**分开发给各自本人**。

把 **活动编号 + 学号 + 邀请码** 告诉对应志愿者即可。

> 志愿者换下一个活动时，需要解除绑定并重新输入新的邀请码。
> 他**参加过活动的记录会保留在手机里**（「记录」页底部 + 绑定页「我参与过的活动」），
> 换活动不会丢 —— 只有尚未上传成功的签到证据会被清除。

### 4.5 现场看板

活动详情 → **「现场看板」**。看到：

- 顶部四态：**已签到 / 待确认 / 未签到**（+ 在岗抽查的 在岗/待确认/超时/豁免）
- 名单每行：学号、姓名、手机号（掩码）、签到状态
- 点任一状态可**筛选**
- 右上角刷新

### 4.6 复核签到

看板 → 点状态为「待确认」的人 → 复核页：

```
李娜 2021002 · 139****0002
证据强度不足（评分 45），已转人工确认        [待确认]

客观证据
  提交时间   2026-10-18 01:02:48
  方式       定位签到
  距签到点   约 8 米
  定位精度   ±35 米

证据评分   45 分
  自动通过需 ≥60 分；30–59 分转人工（就是当前这条）。
  评分只是辅助，最终由你判断。
  +40  围栏内且距中心 8m（≤50m）
  +10  多次采样一致
  -5   定位精度 35m，未达加分档

[驳回]  [通过]
```

**通过后名单立刻变成「已签到」**。

### 4.7 导出

活动详情 → **「导出 CSV」**。默认**脱敏**手机号。
导出的列包含场地网络白名单 —— 事后审计"为什么这次自动通过"时能查到当时配了什么。

### 4.8 多人/多部门共用一台服务器

默认单发布者（一个邀请码 `1111`）。要让几个部门共用，在服务端配置：

```bash
ADMIN_OWNERS="1111:owner-demo-0001,2222:owner-org-b,3333:owner-org-c"
```

- 每个码登录后**只看到、只能改自己名下**的活动
- 网页端（匿名）仍能看到**全部**已发布活动
- ⚠️ 码按组织分发，不要共用；换组织要换码

## 5. 用户端（志愿者）操作指南

### 5.1 绑定活动

需要发布者给你三样东西：**活动编号**、**学号**、**邀请码**。

**最省事的填法**：绑定页顶部有 **「粘贴邀请信息（自动填写）」**。
发布者复制给你的是一整段带标签的文字（活动编号 / 学号 / 邀请码），
点一下这个按钮，三个输入框会自动填好，你只需核对一眼。

也可以手动逐个填 → 「绑定并进入」。

- 「选填：核对身份」可以填**姓名**或**手机号后四位**（填一个就行，对上任意一个即可）
- 绑定后本设备会被记住，活动期间不用重复输
- 手机掉了/换手机：找发布者**重新发码**，旧授权会自动作废

### 5.2 签到

首页显示当前活动卡 → **「去签到」** → **「开始签到」**。

App 会：

1. 申请定位权限（只在你用的时候取一次，不采集持续轨迹）
2. 连续采 3 次定位
3. 上报给服务器判定

结果分三种：

| 结果 | 含义 | 你该做什么 |
|---|---|---|
| **已签到** | 证据充分，自动通过 | 无 |
| **待确认** | 证据强度不足，转人工 | 等发布者复核，通常站得更靠近签到点会更好 |
| **未通过** | 证据不足 | 看提示原因（多数是离得太远） |

> 网络不好时签到会自动存到本地队列，联网后**自动补传**。
> 补传的记录**一律转人工**（补传时间与现场时间不一致，无法排除事后补造）。

### 5.3 在岗确认

签到最后，服务器会按发布者配置的间隔安排**在岗抽查**（默认首次 15 分钟后，之后每 30 分钟）。
若发布者选了「手动抽查」，则不按间隔发，只在他手动点的时候来一条。

> **活动取消或结束后**，还没确认的抽查会自动变成**已豁免**（并给出原因），
> 不会再催你确认，也不会记成缺席。

底部「在岗」标签会显示任务：

- 到点的任务会在**响应窗口内**（默认 5 分钟）要求确认
- 点「确认在岗」→ 上报一次定位
- **未到点不能提前确认**，超时也不能补（超时后联系发布者人工补录）

### 5.4 看记录

底部「记录」标签：

- 我的签到记录（状态、时间、评分、距签到点距离）
- 在岗任务完成情况
- **待上传队列**（还没同步成功的证据）

## 6. 网页端（只读）

浏览器打开 `http://<服务器IP>:8080/`。

能做：

- 浏览活动列表（卡片显示状态、时间、地点、时长）
- 按 **关键词 / 部门 / 状态 / 时间范围** 筛选
- 看统计图
- 打开活动详情
- **导出 CSV**（与筛选条件一致 —— 筛出 12 条就导 12 条）

不能做：

- ❌ 签到、复核、发布、改名 —— 这些只能在 App 里做

> 网页端不登录，匿名可见的只有**已发布/进行中/已结束/已取消**的活动；
> **草稿永远只有发布者自己能看到**。

## 7. 服务端配置参考

配置文件：`server/.env`（从仓库根 `.env.example` 复制一份改名即可）。

| 变量 | 默认 | 说明 |
|---|---|---|
| `HOST` | `0.0.0.0` | `0.0.0.0` 才能被局域网手机访问 |
| `PORT` | `8080` | 端口 |
| `NODE_ENV` | `dev` | `dev` / `test` / `prod` |
| `DB_DRIVER` | `sqlite` | `sqlite`（本地，零依赖）或 `mysql`（生产） |
| `DB_SQLITE_FILE` | `./data/volunteer.db` | SQLite 文件路径 |
| `ADMIN_INVITE_CODE` | `1111` | 管理端邀请码 |
| `ADMIN_OWNERS` | 空 | 多发布者映射，见 §4.8 |
| `ADMIN_TOKEN_TTL_MINUTES` | `720` | 令牌有效期（滑动过期） |
| `LOGIN_MAX_FAILURES` | `5` | 连续失败几次锁定 |
| `LOGIN_LOCK_MINUTES` | `10` | 锁定时长 |
| `STATIC_DIR` | `web/dist` | 前端产物目录；`off` 表示只跑 API |
| `ACCESS_LOG` | `true` | 访问日志 |
| `TOKEN_SECRET` | 空 | `NODE_ENV=prod` 时**必须**≥32 字符 |

改完重启服务端生效。

## 8. 判定规则（为什么有时会转人工）

签到评分（方案 §6.1）：

```
围栏内（精度 ≤50m）        +40
围栏内（50m–半径内）       +25
Wi-Fi 命中场地白名单        +20
校园网 IP 命中白名单        +10
多次采样一致               +10
────────────────────────────────
≥60 自动通过 ／ 30–59 转人工 ／ <30 驳回
模拟定位 −60 且**一票否决**（分数再高也转人工）
```

几条要知道的细节：

- **定位精度 >100 米时该证据不计分**（不是直接驳回）——设备定位劣化是常事
- **围栏外 1.5 倍半径以内给 0 分**（边界抖动不该判死），更远才驳回
- **没有坐标 → 转人工而不是驳回**（可能是定位模块故障，现场还有人工补录）
- **离线补传一律转人工**
- **模拟定位**的判定要求"坐标与精度都完全一致 **且** 精度 ≤5 米"
  —— 静止在室内的真实用户采样一致是正常的，不能误杀

## 9. 常见问题排查

### 9.1 手机连不上服务器

按顺序排查：

1. **同一 Wi-Fi 吗？** 手机和电脑必须同一个网络
2. **手机浏览器能打开 `http://<电脑IP>:8080/api/health` 吗？**
   - 打不开 → 网络/DNS 问题
   - 能打开 → App 里填的地址写错了
3. **Windows 防火墙**是否放行了 8080（最常见）
4. **连的是手机热点？** Android 热点默认有客户端隔离，手机访问不到电脑。
   用数据线方案：`adb reverse tcp:8080 tcp:8080` + 地址填 `127.0.0.1:8080`
5. **电脑 IP 变了吗？** 换 Wi-Fi 后 IP 会变，App 里要重新填

App 里的「测试连接」是**一次定论**：失败最多 6 秒给结论，不会让你等 30 秒。

### 9.2 登录提示"邀请码不正确"

- 默认是 `1111`
- 服务端如果改了 `ADMIN_INVITE_CODE`，要用改后的
- 连续错 5 次会锁定 10 分钟（防暴力猜，不是坏了）

### 9.3 安装 APK 失败

| 报错 | 原因 | 解决 |
|---|---|---|
| `INSTALL_FAILED_USER_RESTRICTED` | 小米/红米需要额外开关 | 打开开发者选项里的 **USB 调试** → **USB 调试（安全设置）** → **USB 安装** 三个开关 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 签名不一致（换了构建环境） | 先卸载旧版再装 |
| `INSTALL_FAILED_NO_MATCHING_ABIS` | 装错架构 | 用 `arm64-v8a` 那个包 |

### 9.4 签到一直"待确认"

99% 是**活动没配场地网络白名单**。见 §4.2。
另外确认你确实站在签到点附近（看结果里的"距签到点"）。

### 9.5 网页能看活动，但 App 看不到

App 登录后看到的是「**我发布的**活动」（只有自己的）。
网页是公开浏览，看到的是**所有人**已发布的。
两者口径不同，不是 bug。

### 9.6 演示模式下"去签到"按钮不出现

活动时间窗过期了。正常情况下 App 启动时会自动把演示活动平移到"进行中"；
若仍有问题，切换一次「切回连接服务器 → 再切回演示模式」即可刷新演示数据。

## 10. 自己构建 / 跑测试

### 环境

- Flutter 3.47+ / Dart 3.13+
- JDK 17
- Android SDK 36
- Node.js 22+（服务端用内置 `node:sqlite`，**零 npm 依赖**）

### 构建 App

```bash
cd apps/user_app        # 或 admin_app
flutter pub get
flutter build apk --release --split-per-abi
# 产物：build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
```

想预置服务器地址（不填也能在 App 里改）：

```bash
flutter build apk --release \
  --dart-define=API_BASE_URL=http://192.168.1.5:8080/api
```

### 跑测试

```bash
# 服务端（136 项）
cd server && npm test && npm run check

# Mock 服务端（172 项）
cd mock_server && npm run smoke

# Flutter 各包
cd packages/shared_core    && flutter test    # 189 项
cd packages/shared_ui      && flutter test    # 38 项
cd packages/shared_platform && flutter test   # 5 项
cd apps/user_app           && flutter test    # 23 项
cd apps/admin_app          && flutter test    # 29 项
```

合计 **592 项**。

端到端测试需要显式指定地址（默认不跑，避免污染正在使用的库）：

```bash
cd packages/shared_core
E2E_BASE_URL=http://127.0.0.1:8080/api flutter test test/e2e_*_test.dart
```

## 11. 已知限制

| 限制 | 说明 |
|---|---|
| 两端 App 演示数据不共享 | Android 沙箱隔离。要共享必须走服务器 |
| 演示模式不能导出 | 没有服务端生成文件（会明确提示） |
| 网页端只读 | 设计如此，写入一律在 App |
| 多发布者无账号体系 | 邀请码即身份，没有吊销/审计界面。校内几个部门够用，再往上应换账号体系 |
| 生产部署未验证 | `Dockerfile` 未实际构建过 |
| 活动时长上限 72 小时 | 跨天长期岗建议拆成多个活动 |

## 附录：三分钟验收清单

给人演示时按这个顺序走，最省时间：

```
【管理端】
1. 登录（1111）
2. 新建活动 → 用当前位置 → 用当前网络 → 发布
3. 名单 → 加人 → 生成邀请码 → 记下三样
4. 现场看板（此时 0 人签到）

【用户端】
5. 填三样 → 绑定 → 去签到 → 开始签到
6. 结果：已签到（评分 60，自动通过）

【管理端】
7. 刷新看板 → 已签到 1 人 → 点开看客观证据与评分明细

【电脑】
8. 浏览器打开 http://<IP>:8080/ → 筛选 → 导出 CSV
```

如果第 6 步得到的是「待确认 / 评分 50」，说明活动没配场地网络 ——
回到第 2 步补上再试。
